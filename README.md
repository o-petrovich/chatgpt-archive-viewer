# ChatGPT Archive Viewer

`ChatGPT Archive Viewer` — локальна програма для збереження та зручного перегляду окремих розмов ChatGPT у вигляді архіву.

Ідея проста:

```text
ChatGPT
   ↓
ChatGPT Helper
   ↓
файли експорту в ~/Downloads
   ↓
ChatGPT Archive Viewer
   ↓
локальний архів чатів з повідомленнями та вкладеннями
```

Viewer не потребує повторного відкривання старої розмови на сайті ChatGPT: після імпорту чат, його зображення та інші вкладення зберігаються локально.

> Проєкт зараз активно розробляється. Формат архіву та інтерфейс ще можуть змінюватися.

---

## 1. Що таке ChatGPT Helper

`ChatGPT Helper` — окреме розширення для браузера, яке використовується для отримання даних конкретної розмови ChatGPT.

Сам `ChatGPT Archive Viewer` не завантажує розмову з ChatGPT. Його задача інша: прийняти вже створений Helper-ом export, розкласти його у локальний архів і показати у зручному HTML-viewer.

У ChatGPT Helper для цього використовується вкладка **Export Conversations**.

Для одного чату достатньо його Conversation ID. Наприклад, якщо адреса розмови має вигляд:

```text
https://chatgpt.com/c/6a7f4b0d-4e70-83ed-9060-e7234ac3ea0d
```

то Conversation ID:

```text
6a7f4b0d-4e70-83ed-9060-e7234ac3ea0d
```

### Де взяти ChatGPT Helper

ChatGPT Helper є окремим проєктом/розширенням і не входить до цього репозиторію.

На цей момент README навмисно не містить вигаданого посилання на інсталяцію Helper. Додайте сюди посилання на офіційний репозиторій або сторінку розширення, з якої встановлюєте вашу версію ChatGPT Helper.

Після встановлення розширення його іконка з'являється у браузері.

## 2. Як отримати архів розмови

1. Відкрийте потрібний чат на `chatgpt.com`.
2. Скопіюйте Conversation ID з адресного рядка браузера — це частина після `/c/`.
3. Відкрийте **ChatGPT Helper**.
4. Перейдіть у **Export Conversations**.
5. Виберіть **By IDs**.
6. Вставте Conversation ID.
7. У секції **Fetch** залиште увімкненими:
   - `Conversations`;
   - `Attachments`.
8. У секції **Output** виберіть `ZIP (auto-split 100 MB)`.
9. Натисніть **Run**.
10. Дочекайтеся повідомлення `Done`.

Helper збереже набір файлів у стандартну папку браузера **Downloads**.

Типовий export виглядає приблизно так:

```text
chatgpt-run-..._conversations.json
chatgpt-run-..._attachments-index.json
chatgpt-run-..._attachments-vol01.zip
chatgpt-run-..._run-manifest.json
```

Якщо вкладень багато, ZIP-томів може бути декілька:

```text
_attachments-vol01.zip
_attachments-vol02.zip
...
```

**Не потрібно вручну розпаковувати ZIP.** Viewer зробить це під час імпорту.

## 3. Встановлення ChatGPT Archive Viewer

Потрібен Python 3 і Git.

Клонування репозиторію:

```bash
git clone git@github.com:o-petrovich/chatgpt-archive-viewer.git
cd chatgpt-archive-viewer
```

На поточному етапі проєкт використовує лише стандартні Python-модулі, тому окремий `pip install` не потрібен.

### Структура програми

```text
ChatGPT_Archive/
├── viewer/
│   ├── index.html
│   ├── app.js
│   ├── v5.js
│   └── style.css
│
├── chats/
│   ├── 2026-08-07_Назва-чату/
│   │   ├── conversation.json
│   │   ├── attachments-index.json
│   │   ├── attachments/
│   │   └── topics.json
│   └── ...
│
├── catalog.json
├── add_archive.py
└── view.py
```

`chats/` містить самі локальні архіви. `catalog.json` — каталог чатів для viewer-а.

---

## 4. Запуск

У каталозі проєкту виконайте:

```bash
python3 view.py
```

`view.py`:

- запускає локальний HTTP-сервер тільки на `127.0.0.1`;
- вибирає вільний локальний порт;
- автоматично відкриває viewer у браузері;
- завжди використовує каталог, у якому фізично знаходиться сам `view.py`.

У терміналі буде приблизно:

```text
ChatGPT Archive Viewer
----------------------
Archive root: /.../ChatGPT_Archive
Serving:      /.../ChatGPT_Archive/viewer/index.html
Downloads:    /home/user/Downloads
URL:          http://127.0.0.1:xxxxx/viewer/index.html
```

Для завершення сервера натисніть:

```text
Ctrl+C
```

## 5. Додавання нового архіву

У лівому верхньому куті viewer-а є кнопка:

```text
+
```

Після натискання Viewer запитує локальний сервер про всі файли:

```text
~/Downloads/*_conversations.json
```

і показує доступні exports.

Виберіть потрібний export і натисніть **Додати архів**.

Перед імпортом програма перевіряє наявність необхідних файлів, зокрема `*_conversations.json` та відповідного `*_attachments-index.json`.

Після успішного імпорту:

- створюється окрема папка чату в `chats/`;
- зберігається `conversation.json`;
- копіюються вкладення;
- створюється локальний `attachments-index.json`;
- створюється початковий `topics.json`;
- оновлюється `catalog.json`;
- вихідні файли цього export з `~/Downloads` видаляються.

Тому `Downloads` після успішного додавання не захаращується вже обробленими export-файлами.

---

## 6. Список архівних чатів

Ліва колонка містить усі імпортовані розмови.

Для кожного чату показуються:

```text
Назва розмови
YYYY-MM-DD HH:MM
```

Дата і час беруться з **першого реального повідомлення розмови**, а не з часу імпорту або назви папки.

Чати сортуються за цією датою і часом — від новіших до старіших.

Це працює також для архівів, імпортованих старими версіями viewer-а: при запуску viewer може визначити час без повторного імпорту.

### Пошук архіву

Поле **Пошук архівів...** фільтрує список чатів за назвою.

---

## 7. Перегляд розмови

Основна область максимально наближена до звичного представлення ChatGPT.

Повідомлення користувача виділяються окремою **синьою бульбашкою**.

Звичайні відповіді ChatGPT показуються окремими блоками.

Viewer намагається не показувати технічну інформацію, яка присутня у сирому export ChatGPT, але не є частиною нормальної розмови, наприклад:

```text
reasoning
reasoning_recap
thoughts
tool calls
container.exec
web.run
execution_output
```

Фільтрація виконується переважно за структурними полями export, а не простим пошуком текстових слів.

Важливий виняток: ChatGPT export може зберігати **згенеровані зображення як `role=tool`**. Viewer розпізнає такі повідомлення і не видаляє їх разом зі службовими tool-записами.

---

## 8. Вкладення та картинки

При імпорті `attachments-index.json` використовується для зв'язування `sediment://...` pointers з реальними файлами у ZIP-томах Helper-а.

Вкладення копіюються всередину папки конкретного чату, тому після імпорту вони більше не залежать від файлів у `Downloads`.

Це дозволяє переглядати старий чат локально разом із його зображеннями.

---

## 9. Середня колонка: «Зміст» і «Питання»

Середня колонка має два режими.

### Зміст

Показує пункти з файлу:

```text
topics.json
```

Поки для нового чату автоматично створюється один початковий пункт:

```text
Огляд чату
```

Архітектура `topics.json` закладена для майбутнього **семантичного змісту великих чатів**. Наприклад:

```text
Pi5 + OpenCV. День 22

1. Waybeam integration
2. Camera mode scan
3. PERF-01 — 8 OpenCV threads
4. PERF-02 — benchmark
5. Connected Components
6. Gaussian Blur
7. Original recording
8. NFS recorder
9. Transport
10. WebRTC bottleneck
11. Поточний стан / наступні кроки
```

У майбутньому клік по такому пункту повинен переводити безпосередньо до відповідного місця довгої розмови.

### Питання

Показує всі повідомлення користувача як навігаційний список:

- питання;
- команди;
- короткі репліки;
- посилання;
- код;
- повідомлення з вкладеннями.

Довге повідомлення скорочується приблизно до 130 символів, але **слово не обрізається посередині**.

Клік по пункту прокручує основний чат точно до відповідного повідомлення.

Для дуже довгих технічних чатів це фактично працює як швидкий покажчик усіх запитів користувача.

---

## 10. Пошук усередині відкритого чату

У верхній частині основної області є поле:

```text
Пошук у чаті...
```

Viewer:

- знаходить входження тексту у відкритій розмові;
- підсвічує знайдений текст;
- показує номер поточного результату і загальну кількість, наприклад `2 / 15`;
- дозволяє переходити між результатами кнопками вгору/вниз.

Це окремий пошук від **Пошуку архівів** у лівій колонці.

## 11. Формат локального архіву

Кожна розмова зберігається незалежно:

```text
chats/
└── 2026-08-07_Червень-Аватарка-Трохи-про-звук-та-сонар/
    ├── conversation.json
    ├── attachments-index.json
    ├── attachments/
    │   ├── ...
    │   └── ...
    └── topics.json
```

Це принципове рішення проєкту: один HTML-viewer використовується для будь-якої кількості локальних архівів, а самі чати не вшиваються в HTML.

---

## 12. Ручний імпорт

Імпорт можна виконати без браузерного інтерфейсу:

```bash
python3 add_archive.py ~/Downloads/chatgpt-run-..._conversations.json
```

Якщо потрібно після успішного імпорту видалити вихідний набір export-файлів:

```bash
python3 add_archive.py ~/Downloads/chatgpt-run-..._conversations.json --delete-source
```

Через кнопку `+` у viewer вихідні файли після успішного імпорту видаляються автоматично.

---

## 13. Що вже корисно у поточній версії

- один viewer для багатьох архівних чатів;
- локальне збереження розмов;
- локальне збереження attachments;
- імпорт без ручного розпакування ZIP;
- вибір export безпосередньо з `~/Downloads`;
- автоматичне очищення обробленого export з `Downloads`;
- сортування чатів за реальним часом першого повідомлення;
- дата **і час** під назвою кожного архіву;
- пошук архіву за назвою;
- пошук тексту всередині відкритого чату;
- підсвічування та навігація по результатах пошуку;
- режим **Питання** як покажчик усіх повідомлень користувача;
- навігація з питання до відповідного місця чату;
- сині бульбашки повідомлень користувача;
- приховування службових reasoning/tool записів;
- підтримка generated images, які в export представлені як tool messages;
- заготовка `topics.json` для майбутнього семантичного змісту.

## 14. Поточний напрямок розвитку

Головна наступна функція — **семантичний зміст довгого чату**.

Мета не просто знайти слово, а перетворити багатогодинну технічну розмову на навігацію за реальними темами та етапами роботи:

```text
великий чат
   ↓
аналіз основних тем
   ↓
topics.json
   ↓
Зміст
   ↓
клік по темі → точне місце у розмові
```

Саме для цього `topics.json` уже є частиною структури кожного архіву.

---

## 15. Приватність

Viewer працює локально.

`view.py` слухає тільки:

```text
127.0.0.1
```

Тобто локальний архів не публікується в Інтернет автоматично.

Водночас самі файли у `chats/` можуть містити повний текст ваших розмов та вкладення. Не додавайте приватні архіви в Git і не публікуйте каталог `chats/` без перевірки його вмісту.
